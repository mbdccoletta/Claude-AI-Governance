# Code review — correctness and robustness

Scope: `hooks/`, `install.*`, `uninstall.*`, `collector/`, `connector/` (workflow, deploy, csv-import, dashboard, dql), `evals/run-evals.sh`.
Method: static read of every file in scope at commit `5206e57`, plus local-only checks (`bash -n`, `python3 -m py_compile`, `node --check`, `connector/test/run_tests.sh` against the loopback mocks, and isolated reproductions of the hook under a throw-away `$HOME`). No installer was run against this machine, no tenant or network endpoint was called. Items that could not be reproduced here are marked **to verify**.

## 1. Summary

The asset is in good shape where it is tested: the connector suite passes end to end (403 events, dedup parity, 429 back-off, cursor-bound pagination), every script parses, the `set -u` empty-array idiom works on bash 3.2, the rendered collector config validated and exported in the recorded e2e run, and `evals/run-evals.sh` contains no `eval` builtin and never prints a secret.

The weak points cluster in three places:

1. **The Claude Code hook's state file is not safe under the parallel tool calls Claude Code actually makes.** Reproduced here: 8 concurrent `PreToolUse` events left 1 of 8 tool records, lost the turn's `trace_id`/`turn_span_id`, and twice left the state file as invalid JSON. Tool spans then get orphaned and the turn is split across trace ids. Same-name tool calls also collide because the record is keyed by `tool_name`, not `tool_use_id`.
2. **The Workflow connector is all-or-nothing against a 110 s task timeout.** API calls are serialized at ≥1.1 s each and nothing is ingested until both reports are fully paged; an org whose cost+usage reports exceed ~90 pages (roughly 2000 users × 10 days) will time out every day and ingest zero events.
3. **Several "works in the demo, not in the field" gaps:** the hook's `gen_ai.usage.cost_usd` comes from a Stop-event field Claude Code does not send (the e2e test fabricates it; five tiles of the shared dashboard read it), `requests` is double-counted when the Enterprise cost report returns it, a `product == "claude_code"` filter in `official-vs-observed-tokens.dql` has slipped into a comment, the installer accepts any string as a token (the reported "token pasted 3× → 401 later" case), and tool input/output always leaves the machine even with prompt capture off.

Nothing in the hook can block Claude Code: `main()` runs in a daemon thread joined at 10 s, every exit path is `sys.exit(0)`, and the HTTP post has a 3 s timeout (a 60 MB transcript was read in 0.34 s).

### Items reviewed and found correct (no finding)

* `install.sh:154, 207, 209, 267` — the `"${arr[@]+"${arr[@]}"}"` idiom under `set -u` expands to **zero** words on bash 3.2.57 when the array is empty (tested with `/bin/bash`; `python argv: []`). No empty `--attr ""` is passed.
* `hooks/otel-hook.py:301-304` — never blocks: daemon thread, `join(10)`, every branch `sys.exit(0)`, HTTP timeout 3 s. A `Stop` against a 60.8 MB / 60 000-line transcript took 0.34 s wall-clock.
* `hooks/otel-hook.py:35-37` — `trunc` precedence is `(s[:n] + marker) if len(s) > n else s`; 5000 chars → 4111.
* `collector/render-config.py` — `$`→`$$` escaping, quote-aware substitution, `transform/native_email` and the `user.email` resource line dropped when no e-mail, `transform/redact_content` removed only with `--capture-prompts`.
* `collector/otel-collector.yaml` OTTL: `delete_matching_keys`, `delete_key`, `set(...) where ... == nil`, `context: spanevent/log/datapoint` are valid for 0.163.x; the e2e log shows `otelcol-contrib version 0.163.1` validating, starting (`Server available`) and exporting to all three paths, with `gen_ai.provider.name` aliased and `claude.account_email` moved.
* `connector/workflow/lib/common.js:157-178` — cursor params frozen (`Object.freeze({...baseParams})`), only `page` appended, `has_more && next_page` termination, one 410 restart. Mock returns 400 on a param change and the suite passed, so params never changed mid-cursor.
* `common.js:65-74` — `daysAgo` builds UTC midnight via `Date.UTC`; checked across a DST date: `2026-03-29T00:00:00.000Z` / `2026-03-28T00:00:00.000Z`.
* `common.js:54-58` — `centsToUsd("41280.000000") = 412.8`, `centsToUsd(2550) = 25.5`.
* `common.js:47-50` vs `import_team_spend.py:71-74` — dedup.key parity asserted by the suite (`PARITY_OK`) for the same tuple; both use `""` for null parts and the first 32 hex chars of SHA-256.

* `evals/run-evals.sh` — **no `eval` builtin** anywhere (the 54 matches of the substring are `dt_evals`/`evals`). `--since`, `--sample`, `--provider`, `--service`, `--metrics` are validated against regexes/allowlists before use; `--model`/`--env-url` flow only into the generated YAML (self-inflicted). `--dry-run` exits before `need_node`/network (line 277-281); real runs require a TTY or `--yes` (line 287); token/key presence is reported as `environment`/`evals/.env`/`missing` only — values are never printed.
