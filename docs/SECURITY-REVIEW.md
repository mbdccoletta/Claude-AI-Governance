# Security review — dt-ai-observability-claude

Independent read-only review of the asset at commit `85b2eb5` (2026-10-19). Static analysis only: every file in the repo was read; `python3 -m py_compile` and `node --check` were run on the Python and JavaScript sources; no installer, collector, tenant or network call was executed. `shellcheck`, `bandit` and `semgrep` were not available on the review machine (to run before release, see checklist).

## 1. Summary and overall risk

**Overall risk: Medium.** The asset gets the hard parts right: the ingest token lives in the OS credential store and is only ever an environment variable of the collector process; the rendered config and `config.env` are mode 0600 and contain no token; every receiver binds to loopback; prompt/response capture is off by default and enforced twice (hook flag plus a collector `transform` processor that also strips native `prompt` log attributes and span events); downloads are SHA-256 checked; the workflow reads the Anthropic key from the credential vault with `APP_ENGINE` scope and never logs it; the deploy script is dry-run by default.

The findings that matter are about **scope of what is exported and logged by default**, not about the token:

1. **Tool-call input and output are exported and written to a local log by default** (`claude.tool_input` / `claude.tool_response`, 4 KiB each). These carry Bash command lines, file contents written by `Write`/`Edit` and file contents returned by `Read`, which routinely include secrets (`.env`, keys in `curl -H`). The collector's redaction processor does not cover these keys, so "no prompt content by default" is true but "no sensitive content by default" is not.
2. **The workflow trusts run parameters for the Anthropic base URL and the credential to read.** Anyone who can run or edit the workflow can point it at another vault credential and another host, within the JS-runtime outbound allowlist. The deploy script creates the vault entry with `ownerAccessOnly: false` and the workflow with `isPrivate: false`, widening who can do that.
3. **The collector's debug exporter is on by default** and `collector.log` has no rotation and default permissions; it contains user e-mail, Claude account ids, tool I/O and, with `--capture-prompts`, prompts and responses.
4. **Supply chain**: `otelcol-contrib` is fetched as `latest` with a same-origin checksum (integrity, not authenticity, no signature check), and evals run `npx -y @dynatrace-oss/dt-evals@latest`.

No hard-coded secrets, tenant ids or real e-mail addresses were found in the repository (regex sweep for `dt0c01.`, `dt0s..`, `sk-ant-`, `ghp_`, `*.live|apps.dynatrace.com`, e-mail addresses; only `example.com` and placeholders).

## 3. Verified as good

**Secrets**
- Token is prompted with `read -s` / `Read-Host -AsSecureString` (`install.sh:119`, `install.ps1:80`); stored in Keychain (`install.sh:249`), Secret Service via stdin (`:251`), or a 0600 file written under `umask 077` with an explicit warning (`:255-256`); DPAPI current-user blob plus an owner-only ACL on Windows (`install.ps1:176-182`). `unset TOKEN` after storage (`install.sh:259`), `Remove-Variable Token` (`install.ps1:77`).
- The collector config keeps `${env:DT_INGEST_TOKEN}` as an env reference (`render-config.py:56-57`); config validation uses a placeholder (`install.sh:282`, `install.ps1:204-206`). `otel-collector.yaml` and `config.env` are 0600 (`install.sh:268,280`). The wrapper `exec`s the collector so the token exists only in that process's environment (`run-collector.sh:24-25`); on Windows the BSTR is zeroed (`run-collector.ps1:7-9`).
- `test/sink.py:56` never prints the Authorization value; the mock vault key is a fake (`run_tests.sh:9`); `.gitignore` covers `evals/.env`, `evals/.dt-eval.yaml`, `connector/deploy/.out/`, `test/sink-data/`, `test/sink.log`.
- Workflow: key read only through `credentialVaultClient.getCredentialsDetails` (`common.js:195`), never returned, logged or embedded in the workflow JSON; `resolve_config.js:36` logs the credential *name/id* only; error bodies are truncated to 400 chars (`common.js:148`). `deploy.sh:81` reads the key from an env var and the dry-run output prints `$VAR`, not the value (`:90`).

**Network / exposure**
- All receivers and the health extension bind to `127.0.0.1` (`otel-collector.yaml:20,22,98`); collector self-metrics disabled so port 8888 is not opened (`:103`). Outbound is HTTPS to the tenant with gzip (`:89-94`); `.apps.` hosts are refused and `http://` endpoints warned (`install.sh:138-141`). PowerShell forces TLS 1.2 (`install.ps1:39`). The hook only ever talks to `127.0.0.1` with a validated port range (`otel-hook.py:68-76`).

**Privacy**
- Prompt/response capture is off by default and enforced independently in the hook (`otel-hook.py:266-283`) and in the collector (`otel-collector.yaml:42-57`, covering span attributes, span events and the native `prompt` log attribute); `render-config.py:91-94` removes the processor only on `--capture-prompts`. The e2e test asserts no prompt text reaches the sink (`test/run-local-test.sh:91-92`). The hook strips `<system-reminder>` blocks before storing the prompt (`otel-hook.py:26-33`). Reserved `_` keys cannot be set via `--attr` (`configure-hooks.py:148`, `render-config.py:77`). Native account e-mail is renamed to `claude.account_email` so the installer-provided identity wins (`otel-collector.yaml:73-84`). dt-evals runs are opt-in, confirmed interactively, refuse non-interactive shells without `--yes`, and store evaluated text only with `--store-evaluated-prompt` (`run-evals.sh:284-291,249`).

**Supply chain / integrity**
- SHA-256 verification of the download (`install.sh:217-222,239`; `install.ps1:138-142,166`); `tar` extracts only the named member (`install.sh:227,240`; `install.ps1:147,167`); temp dir removed by `trap` / `finally`; `--otelcol-tarball` supports air-gapped installs with optional `.sha256`. Version can be pinned (`--otelcol-version`, `DT_AI_OBS_OTELCOL_VERSION`). `python3 -I` is used for every helper so a planted module in cwd cannot be imported (`install.sh:202,209,267`).

**Robustness / fail-safe behaviour**
- `set -euo pipefail` and quoted variables in every shell script; `configure-hooks.py` aborts on invalid JSON instead of clobbering `settings.json` (`:53`), writes atomically via `os.replace` (`:63-67`), and never removes or replaces hook groups it did not create (`:78-82,96-98`). The uninstaller checks the asset marker before deleting the hook (`uninstall.sh:67`). The hook caps attribute size at 4096 (`otel-hook.py:19`), times out HTTP at 3 s and the whole run at 10 s so Claude Code is never blocked (`:133,304`). `cmd_native_otel` refuses to overwrite foreign values (`configure-hooks.py:172-174`).
- Workflow: retries bounded (`maxRetries 5`, 30 s cap, honours `Retry-After`, `common.js:137-145`), one cursor restart on 410 (`:166-171`), task timeout 110 s and `hourlyExecutionLimit: 10` (`build.py:70,84`), `org_type` whitelisted and lookback clamped 1–31 (`resolve_config.js:28-33`). `merge_allowlist.py:36-40` appends and never drops existing hosts; `deploy.sh` mutates nothing without `--yes` (`:53`).
- `import_team_spend.py` validates `--date` (`:180`), checks HTTP status (`:201`), has a `--dry-run` path (`:187`).

## 4. Recommended hardening checklist

Ordered by value; items map to findings in brackets.

- [ ] Redact `claude.tool_input` / `claude.tool_response` in the collector unless `--capture-prompts` (or a new `--capture-tool-io`), and add a pattern-based secret scrubber for common token formats in `transform/redact_content`. Update README "Privacy". [F1]
